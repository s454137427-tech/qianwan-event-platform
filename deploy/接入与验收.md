# 前湾 MEGA 双赛事平台 · 资源接入与验收

当前版本：2.1.0，整理日期：2026-10-08。可在本机运行；正式域名、微信和腾讯云资源由你后续配置。

## 1. 先在本机运行

安装 Node.js 24 或以上、pnpm 11.25.0。在项目根目录执行：

```text
pnpm install --frozen-lockfile --ignore-scripts
pnpm run setup
pnpm start
```

Windows 也可以双击根目录的 `启动预览.cmd`。网站为 http://127.0.0.1:3000，后台为 http://127.0.0.1:3000/admin.html。首次启动随机生成的本地管理员密码在 `var/本地后台登录.txt` 中。本地体验使用虚构资料；体验账号与本地数据不迁入正式数据库。

`pnpm run setup` 只在配置文件不存在时创建它，重复运行保留已填写的配置。它还创建证书、微信验证文件目录，不购买或创建云资源。

## 2. 填写一份正式配置

正式配置位于 `deploy/.env.production`；模板为同目录的 `.env.production.example`。这个文件仅留在部署主机，不发送给别人。含空格的说明文字使用双引号包围。

| 资源 | 配置字段 | 需要你提供 |
| --- | --- | --- |
| 子域名 | `APP_ORIGIN` | 完整 HTTPS 来源，例如 `https://活动子域名`，不含路径 |
| 公众号 | `WECHAT_APPID`、`WECHAT_SECRET` | 具备网页授权能力的公众号真实凭据 |
| PostgreSQL | `DATABASE_URL`、`DATABASE_SSL` | 独立正式数据库、连接地址和受信 TLS 配置 |
| Redis | `REDIS_URL` | 应用可访问的缓存连接，按资源配置使用 redis 或 rediss |
| 私有 COS | `COS_SECRET_ID`、`COS_SECRET_KEY`、`COS_BUCKET`、`COS_REGION` | 受限后台凭据、私有桶和地域 |
| 后台 | `ADMIN_USERNAME`、`ADMIN_PASSWORD` | 初始管理员账号与至少 16 位密码 |
| 活动说明 | `ORGANIZER_NAME`、`CONTACT_TEXT`、`PRIVACY_NOTICE`、`RULES_CONFIRMED` | 实际运营主体、联系渠道、隐私说明和已确认规则 |
| 活动时间 | 四项截止时间、`EVENT_END_AT` | 完整时间，例如 `2026-10-30T18:00:00+08:00`，以真实安排为准 |

本地 `.env` 与正式 `deploy/.env.production` 分开使用。生产环境禁止体验登录，缺少正式资源配置会拒绝启动。初始化密码只在首次创建管理员时生效，修改该值不会重置已有账号。

## 3. 子域名与 HTTPS

将子域名解析到入口服务器。在项目根目录执行：

```text
pnpm deploy:prepare
```

脚本从 `APP_ORIGIN` 生成 `deploy/nginx.container.conf`，只生成入口配置，不连接云服务。它会覆盖该生成文件；自定义代理结构时应编辑 `deploy/nginx.conf.template` 后再生成。当前模板支持直接访问的单层 Nginx 入口和两个应用实例；增加云负载均衡时，要同步修改可信代理及转发头策略。

放置证书：

```text
deploy/certs/fullchain.pem
deploy/certs/privkey.pem
```

微信给出的 `MP_verify_*.txt` 验证文件放入 `deploy/wechat-verification/`。部署后可从 `https://正式子域名/MP_verify_实际文件名.txt` 访问。只提供匹配的验证文本文件，其余文件不会由这个目录公开。

## 4. 微信权限

在公众号侧配置实际网页授权域名、入口菜单与平台要求的域名验证。

- 网站入口：`https://正式子域名/`
- 服务端回调：`https://正式子域名/api/auth/wechat/callback`
- 微信内：网页授权后返回网站。
- 普通浏览器：扫描网站生成的二维码，在手机微信授权并确认，原浏览器完成登录。

两条路径使用同一个公众号网页授权流程。昵称和头像以实际授权结果为准；姓名、手机号和身份资料仍需参赛者填写并由工作人员核验。真实公众号权限、微信客户端兼容性和真实授权结果需接入后验证。

## 5. 腾讯云资源

这份部署方案连接外部 PostgreSQL、Redis 和 COS；应用容器只运行业务代码。数据库与缓存限制为应用可访问，数据库开启备份并验证恢复。`DATABASE_SSL=true` 使用受信证书校验；如需要自定义 CA，可按部署环境配置 `NODE_EXTRA_CA_CERTS`。

COS 桶应为私有。CORS 只允许实际活动 HTTPS 来源，允许上传 SDK 需要的请求方法与请求头，暴露 `ETag`。浏览器临时凭证只写单个 `private/<账号>/<任务>.<扩展名>` 对象；服务端核对大小、文件头和 ETag 后复制到 `protected/`，完成文件不允许浏览器覆盖。后台凭据需有指定源目录读取、受保护目录复制写入与申请临时凭证权限。

COS 的断点续传、条件复制、临时凭证实际权限和私有读取需在真实桶中联调。暂存与受保护副本均占用空间；数据库容量额度不等于云账单上限。为 COS 配置实际存储、流量和费用告警。

视频默认签发短期 COS 读取地址。可选 CDN 需先配置私有回源及所有路径的 TypeA 鉴权，再填写 `VIDEO_CDN_*`；未配置 CDN 不影响基础服务启动。身份照片及待审视频继续受访问权限保护。没有自动转码，需验证真实视频在微信中的播放兼容性。

## 6. 在服务器启动

部署主机安装 Docker 与 Compose，开放 HTTPS 入口所需端口。解压部署包，在其根目录操作。若服务器未安装 Node.js，可先构建镜像，再使用下方容器检查命令。

```text
pnpm deploy:check
docker compose -f deploy/compose.yaml build
docker compose -f deploy/compose.yaml up -d
docker compose -f deploy/compose.yaml ps
docker compose -f deploy/compose.yaml logs --tail=100 app1 app2
```

容器检查正式配置的替代命令：

```text
docker compose -f deploy/compose.yaml run --rm --no-deps app1 node scripts/check-deployment.js
```

入口配置需要事先生成。服务器无 Node.js 时，也可在本机填写仅含实际域名的生产模板、生成入口文件，再将该文件交给部署主机；真实密钥只在部署主机填写。

首次数据库建表使用事务与跨实例初始化锁，记录结构版本。已有表以增量方式登记第一版，不删除旧表或数据；后续改表应增加迁移版本，勿修改已执行的版本。两个应用实例共享正式数据库、缓存和私有桶。应用端口不直接暴露公网。

`/api/health` 检查数据库，`/api/ready` 检查数据库与 Redis。配置检查只校验格式和必要字段；就绪检查不验证微信、COS 或容量。单主机两个实例仍有主机与入口单点，需要按实际可用性目标决定是否改为跨主机和云负载均衡。

## 7. 接入后的验收顺序

1. 验证 HTTPS 和微信验证文件，再在微信内与普通浏览器完成两条登录路径。
2. 提交测试报名、上传身份照片和真实视频；测试暂停、重新选择同一文件续传，以及完成文件不能被旧凭证替换。
3. 后台审核资料和作品；访客只能看到通过审核的视频，身份照片和未通过作品不能被公开读取。
4. 造物录取、签到、成果提交；影像投票、造物 3 票额度、角色权限与多个评委评分。
5. 验证投票暂停、截止时间、报名和成绩导出，再测试备份恢复与计划峰值。
6. 确认正式规则和运营资料，在后台开启报名与投票。新正式数据库默认关闭这两个开关。

本地自动化测试与模拟微信响应验证代码行为，不能代替真实资源验收。当前环境没有 Docker，镜像与 Nginx 尚需在部署主机验证；没有声称已验证目标峰值。

视频建议约 3 分钟、默认最大 500MB；时长当前是提示。活动结束后默认保留 15 天，后台显示保留计划，尚未自动删除参赛材料。最终封榜、自动清理、短信验证码和微信分享卡片均需另行实现或确认，当前交付不包含这些流程。
