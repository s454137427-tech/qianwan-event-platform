## 1. 先在本机运行

安装 Node.js 24 或以上、pnpm 11.25.0。在项目根目录执行：

```text
pnpm install --frozen-lockfile --ignore-scripts
pnpm run setup
pnpm start
```

Windows 也可以双击根目录的 `启动预览.cmd`。网站为 http://127.0.0.1:3000，后台为 http://127.0.0.1:3000/admin.html。首次启动随机生成的本地管理员密码在 `var/本地后台登录.txt` 中。本地体验使用虚构资料；体验账号与本地数据不迁入正式数据库。

`pnpm run setup` 只在配置文件不存在时创建它，重复运行保留已填写的配置。它还创建证书、微信验证文件目录，不购买或创建云资源。

## 2. 填写一份正式配置

正式配置位于 `deploy/.env.production`；模板为同目录的 `.env.production.example`。这个文件仅留在部署主机，不发送给别人。含空格的说明文字使用双引号包围。

| 资源 | 配置字段 | 需要你提供 |
| --- | --- | --- |
| 子域名 | `APP_ORIGIN` | 完整 HTTPS 来源，例如 `https://活动子域名`，不含路径 |
| 公众号 | `WECHAT_APPID`、`WECHAT_SECRET` | 具备网页授权能力的公众号真实凭据 |
| PostgreSQL | `DATABASE_URL`、`DATABASE_SSL` | 独立正式数据库、连接地址和受信 TLS 配置 |
| Redis | `REDIS_URL` | 应用可访问的缓存连接，按资源配置使用 redis 或 rediss |
| 私有 TOS | `TOS_ACCESS_KEY_ID`、`TOS_ACCESS_KEY_SECRET`、`TOS_BUCKET`、`TOS_REGION`、`TOS_UPLOAD_ROLE_TRN`、`TOS_PUBLIC_ORIGIN`、`TOS_ENDPOINT` | 受限IAM后台权限、上传角色、私有桶、地域及绑定桶的HTTPS媒体域名 |
| 后台 | `ADMIN_USERNAME`、`ADMIN_PASSWORD` | 初始管理员账号与至少 16 位密码 |
| 活动说明 | `ORGANIZER_NAME`、`CONTACT_TEXT`、`PRIVACY_NOTICE`、`RULES_CONFIRMED` | 实际运营主体、联系渠道、隐私说明和已确认规则 |
| 活动时间 | 报名、影像投稿与投票截止时间、`EVENT_END_AT` | 完整时间，例如 `2026-10-30T18:00:00+08:00`，以真实安排为准 |

本地 `.env` 与正式 `deploy/.env.production` 分开使用。生产环境禁止体验登录，缺少正式资源配置会拒绝启动。初始化密码只在首次创建管理员时生效，修改该值不会重置已有账号。

## 3. 子域名与 HTTPS

将子域名解析到入口服务器。在项目根目录执行：

```text
pnpm deploy:prepare
```

脚本从 `APP_ORIGIN` 生成 `deploy/nginx.container.conf`，只生成入口配置，不连接云服务。它会覆盖该生成文件；自定义代理结构时应编辑 `deploy/nginx.conf.template` 后再生成。当前模板支持直接访问的单层 Nginx 入口和两个应用实例；增加云负载均衡时，要同步修改可信代理及转发头策略。

放置证书：

```text
deploy/certs/fullchain.pem
deploy/certs/privkey.pem
```

微信给出的 `MP_verify_*.txt` 验证文件放入 `deploy/wechat-verification/`。部署后可从 `https://正式子域名/MP_verify_实际文件名.txt` 访问。只提供匹配的验证文本文件，其余文件不会由这个目录公开。

## 4. 微信权限

在公众号侧配置实际网页授权域名、入口菜单与平台要求的域名验证。

- 网站入口：`https://正式子域名/`
- 服务端回调：`https://正式子域名/api/auth/wechat/callback`
- 唯一参与者登录入口：手机号 + 密码。首次填手机号并设置密码即完成注册，之后用同一手机号登录。
- 登录不依赖微信、短信或任何第三方账号；忘记密码由管理员在后台重置，用户不能自助找回。
- 同一手机号连续输错 5 次密码后锁定 15 分钟，防止批量试探。

扫码后的手机授权使用公众号网页授权流程，仍需配置真实公众号及网页授权域名。昵称和头像以实际授权结果为准；姓名、手机号和身份资料仍需参赛者填写并由工作人员核验。真实公众号权限、微信客户端兼容性和真实授权结果需接入后验证。

## 5. 火山云资源

采用火山ECS+私有TOS，PostgreSQL和Redis可以使用托管服务或现有同机Compose扩展。完整配置、IAM策略示例、CORS、独立HTTPS媒体域名、V4签名、受保护副本、费用控制与实测清单见 [火山TOS接入](火山TOS接入.md)。同机数据库不开放公网端口；托管数据库按实际TLS与私网白名单配置。DATABASE_SSL=true时校验受信证书，私有CA可通过挂载及NODE_EXTRA_CA_CERTS指定。

报名材料、待审视频始终保留私有权限；浏览器只获单个暂存对象的1800秒凭据，确认后复制到服务端独占protected路径。短期播放链接600秒。原腾讯CDN的TypeA协议不能用于TOS，本次已禁用VIDEO_CDN启用参数；媒体域名须直接绑定TOS桶。

## 6. 在服务器启动

部署主机安装 Docker 与 Compose，开放 HTTPS 入口所需端口。解压部署包，在其根目录操作。若服务器未安装 Node.js，可先构建镜像，再使用下方容器检查命令。

```text
pnpm deploy:check
docker compose --env-file deploy/.env.production -f deploy/compose.yaml build
docker compose --env-file deploy/.env.production -f deploy/compose.yaml up -d
docker compose --env-file deploy/.env.production -f deploy/compose.yaml ps
docker compose --env-file deploy/.env.production -f deploy/compose.yaml logs --tail=100 app1 app2
```

容器检查正式配置的替代命令：

```text
docker compose --env-file deploy/.env.production -f deploy/compose.yaml run --rm --no-deps app1 node scripts/check-deployment.js
```

入口配置需要事先生成。服务器无 Node.js 时，也可在本机填写仅含实际域名的生产模板、生成入口文件，再将该文件交给部署主机；真实密钥只在部署主机填写。

首次数据库建表使用事务与跨实例初始化锁，记录结构版本。已有表以增量方式登记第一版，不删除旧表或数据；后续改表应增加迁移版本，勿修改已执行的版本。两个应用实例共享正式数据库、缓存和私有桶。使用同机数据库时按火山手册在所有命令中增加 `-f deploy/compose.volcengine.yaml`。应用端口不直接暴露公网。

`/api/health` 检查数据库，`/api/ready` 检查数据库与 Redis。配置检查只校验格式和必要字段；就绪检查不验证微信、TOS 或容量。单主机两个实例仍有主机与入口单点，需要按实际可用性目标决定是否改为跨主机和云负载均衡。

## 7. 接入后的验收顺序

1. 验证 HTTPS，再验证手机号注册、登录、重复注册提示、连续错误锁定与密码重置；清理浏览器 Cookie 后应回到未登录状态。
2. 提交测试报名、上传身份照片和真实视频；测试暂停、重新选择同一文件续传，以及完成文件不能被旧凭证替换。
3. 后台审核资料和作品；访客只能看到通过审核的视频，身份照片和未通过作品不能被公开读取。
4. 影像资格核验、作品审核、公众投票、角色权限与多个评委评分；取消活动的旧接口应拒绝请求。
5. 验证投票暂停、截止时间、报名和成绩导出；在“数据导出”下载甲方备案包与内部留存包，核对汇总、明细、个人信息范围和文件校验，再测试备份恢复与计划峰值。
6. 确认正式规则和运营资料，在后台开启报名与投票。新正式数据库默认关闭这两个开关。

本地自动化测试与模拟微信响应验证代码行为，不能代替真实资源验收。当前环境没有 Docker，镜像与 Nginx 尚需在部署主机验证；没有声称已验证目标峰值。

## 8. 活动结束后的归档

管理员先关闭报名投稿和投票，完成审核与评分，再在“数据导出”分别下载甲方备案包、内部留存包。两版均包含7张CSV表、归档说明和SHA256校验清单。甲方版对姓名、手机号脱敏，排除证件号码、身份证明文件、审核备注和私有存储路径；内部版供授权负责人核对留存，不作为公开资料。视频和身份材料原文件须从私有存储另行备份，数据库备份须验证恢复。

保留原始CSV、校验清单和统计时间；Excel导入手机号和证件号码时选择文本列。每次导出记录当前实时成绩，不会自动生成封榜或获奖结果。PostgreSQL使用同一repeatable-read事务读取全部表，正式环境仍需在目标数据规模与双实例条件下验收。超过10万条记录或64MB归档范围会明确报错，应安排数据库备份导出。

视频建议约 3 分钟、默认最大 500MB；时长当前是提示。活动结束后默认保留 15 天，后台显示保留计划，尚未自动删除参赛材料。最终封榜、自动清理、短信验证码找回密码和微信分享卡片均需另行实现或确认，当前交付不包含这些流程。`lib/sms.js` 已备好短信通道适配器但未接入登录流程。
